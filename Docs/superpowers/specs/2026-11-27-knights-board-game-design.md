# 기사단 게임 설계

작성일: 2026-11-27 · 브랜치: `GamePlay`

## 1. 의도

Canape 엔진의 `Game` 프로젝트에 **사람들이 재미있게 플레이할** 보드게임 "기사단 게임"을 만든다.
아트 리소스는 아직 제작 중이라 화면은 **임시 2D UI**(엔진 게임 UI 시스템)로만 구성한다.
나중에 아트가 들어오면 화면만 교체하고 룰은 손대지 않는 것이 이번 구조의 핵심 목표다.

게임의 재미는 "남들이 몇 명을 보낼지 모르는 눈치 싸움"과 "공개되는 순간의 긴장"에서 나온다.
룰 판정이 정확하고, 공개·정산이 한눈에 이해되어야 한다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 타이틀 씬 → "게임 시작" → 게임 씬으로 이동하면 즉시 1게임(8라운드) 시작.
- 플레이어 1명 + AI 4명, 아래 룰 전부 구현.
- 룰 코어를 엔진과 분리하고, 화면 없는 자동 테스트로 룰을 검증.
- AI가 뻔하지 않게: 성향 차이 + 약간의 무작위성.

**비목표 (이번 범위 아님)**
- 3D 보드·모델·애니메이션, 사운드, 저장/불러오기, 온라인/로컬 다인 플레이, 난이도 선택, 튜토리얼, 다국어.

**반목표 (돌아가도 실패로 보는 것)**
- AI가 공개 전의 남의 깃발·기사 배치를 읽는 것(치팅).
- 12번 점수 분배 등 룰이 틀리게 계산되는 것.
- 무슨 일이 일어났는지 로그를 읽어야만 알 수 있는 화면(정산 결과가 화면에서 바로 보여야 함).
- AI 차례에 화면이 멈추는 것.

## 3. 게임 룰 (확정본)

`[사용자]` = 사용자가 정한 것, `[제안]` = 설계자가 채운 것(사용자에게 제시, 이의 없음), `[빌더 재량]` = 구현자가 정해도 되는 것.

사용자 원본 룰 1~15번과의 대응: 1·2 → 3.1·3.7, 3 → 3.2, 4·5 → 3.1, 6~9 → 3.3, 10·11 → 3.2·3.3-1, 12 → 3.4, 13 → 3.5, 14 → 3.6, 15 → 3.1. 원본에 있는데 여기 빠진 룰은 없다.

### 3.1 구성
- 라운드: 총 **8라운드**. `[사용자]`
- 플레이어: 플레이어 1 + AI 4 = 5명. `[사용자]`
- 시작 자원: 각자 **깃발 2개, 기사단원 5명**, 점수 0. `[사용자]`
- 깃발은 매 라운드 다시 2개를 받는다(소모되지 않음). `[제안]`
- 모든 플레이어의 **점수와 보유 기사 수는 항상 공개**. `[사용자]`

### 3.2 지역 (6곳)

| # | 지역 | 종류 | 몬스터 점수 범위 |
|---|------|------|------------------|
| 1 | 고블린 둥지 | 몬스터 | 1 ~ 3 |
| 2 | 오크 야영지 | 몬스터 | 3 ~ 6 |
| 3 | 트롤 다리 | 몬스터 | 5 ~ 9 |
| 4 | 드래곤 동굴 | 몬스터 | 8 ~ 12 |
| 5 | 훈련소 | 고정 증원 | — |
| 6 | 용병 시장 | 주사위 증원 | — |

- 몬스터 4곳·증원 2곳 구성은 `[사용자]`, 이름과 점수 범위는 `[제안]`. 범위는 데이터 한 곳(테이블)에 두어 밸런스 조정이 쉬워야 한다.

### 3.3 라운드 흐름

1. **라운드 시작**: 각 몬스터 지역의 점수를 그 지역 범위 안에서 균등 무작위로 새로 뽑고, 용병 시장 주사위(1~6)도 굴려 **즉시 모두에게 공개**한다. `[사용자: 공개 시점]` (주사위 공개는 2026-11-27 사용자 요청으로 변경)
2. **깃발 단계**: 플레이어부터 AI 1→4 순으로 차례가 돌아간다. 각자 **깃발 2개를 모두, 서로 다른 지역에** 꽂는다(0개·1개·같은 지역 2개 불가). `[사용자]`
   다른 사람의 깃발은 모두가 꽂을 때까지 보이지 않는다(화면에는 "깃발 완료" 표시만). `[사용자]`
   차례 순서는 매 라운드 동일(플레이어 먼저). 정보가 숨겨지므로 순서는 결과에 영향이 없다. `[제안]`
3. **깃발 공개**: 모든 깃발을 공개한다. `[사용자]`
4. **기사 배치 단계**: 각자 자기 깃발이 있는 **몬스터 지역**에 보유 기사를 나눠 보낸다. 0명도 가능, 합은 보유 기사 수 이하. `[사용자]`
   증원 지역에는 기사를 보내지 않는다(깃발만으로 참여). `[제안]`
   다른 사람의 배치는 모두가 배치할 때까지 보이지 않는다. `[사용자]`
5. **기사 공개**: 모든 배치를 공개한다. `[사용자]`
6. **정산**: 지역 1→6 순서로 하나씩 처리하고 화면에 차례로 보여 준다. 규칙은 3.4~3.6.
7. 라운드 종료 → 다음 라운드. 8라운드 정산 후 게임 종료(3.7).

### 3.4 몬스터 지역 정산 (12번 룰)

몬스터 점수 `S`, 그 지역에 보낸 기사 총합 `T`(모든 플레이어 합).

- `T == 0`: 아무 일 없음.
- `S > T`: **전멸**. 그 지역에 보낸 모든 기사가 각 플레이어 보유에서 사라진다. 아무도 점수를 얻지 않는다. `[사용자]`
- `S <= T`: 승리. 보낸 기사는 점수 분배와 무관하게 **모두 살아서 돌아온다**(전멸이 아니면 사라지지 않음). `[제안]` — 12번 룰 "지면 전멸해 사라진다"에서 읽은 해석으로, 라운드 흐름 설명 때 사용자에게 제시했고 이의 없음.
  따라서 기사는 전멸로만 줄고, 증원 2곳으로만 늘어난다.
  점수 분배:
  1. 기사를 1명 이상 보낸 플레이어를 보낸 수 `c` 기준으로 묶고, `c`가 작은 묶음부터 처리한다. 남은 점수 `R = S`.
  2. 묶음 인원 `n`일 때, `R >= c × n`이면 묶음의 각자가 `c`점을 얻고 `R -= c × n`.
  3. 아니면 묶음의 각자가 `floor(R / n)`점을 얻고, 나머지는 **폐기**, 분배 종료. `[사용자: (가)안]`
  4. `R == 0`이 되면 분배 종료(남은 묶음은 0점).

검증 예시 (테스트 케이스로 그대로 쓴다):

| S | 배치 | 결과 |
|---|------|------|
| 1 | A1, B1 | 둘 다 0점, 1점 폐기 (사용자 예시) |
| 5 | A2, B5 | A 2점, B 3점 (사용자 확정) |
| 4 | A1, B3 | A 1점, B 3점 |
| 5 | A2, B2, C3 | A 2, B 2, C 1 |
| 5 | A3, B3 | A 2, B 2, 1점 폐기 |
| 7 | A2, B3 | 전멸 (T=5 < 7), A·B 기사 각각 2·3명 잃음 |
| 3 | A3 | A 3점 |
| 3 | A0(깃발만) | 아무 일 없음 |

### 3.5 훈련소 (13번 룰)
깃발을 꽂은 플레이어 전원이 기사 1명을 받는다. `[사용자]`

### 3.6 용병 시장 (14번 룰)
주사위(1~6)는 **라운드 시작에 굴려 공개**한다. `[사용자]` 정산 때 깃발을 꽂은 인원 `n`으로 나눠 각자 `floor(d / n)`명을 받고 나머지는 폐기. `[사용자]`
(주사위 1에 깃발 2개 이상이면 아무도 못 받는 경우가 이 식에 포함된다. 깃발이 없으면 아무도 받지 않는다.)

증원으로 받은 기사는 정산이 끝난 뒤 보유에 더해져 **다음 라운드부터** 쓸 수 있다. `[제안]`

### 3.7 승패
- 8라운드 후 점수 최고 1인이 승리. `[사용자]`
- 동점이면 남은 기사 수가 많은 쪽, 그래도 같으면 공동 우승. `[제안]`

## 4. 구조 (사용자 선택: A안 "룰 코어 + UI 컨트롤러 분리")

### 4.1 검토한 방식

| 안 | 내용 | 장점 | 단점 |
|----|------|------|------|
| **A (선택)** | 엔진 무관 순수 C++ 룰 코어 + 화면 담당 스크립트 | 룰 단독 테스트, 아트 교체 시 화면만 교체 | 파일 수가 조금 많음 |
| B | 엔진 `StateMachine`/`FsmState`로 단계 진행 | 에디터에서 흐름이 보임 | 룰이 상태 스크립트에 흩어지고 UI 대기와 섞여 테스트 어려움 |
| C | 스크립트 하나에 전부 | 가장 빨리 화면이 뜸 | 12번 같은 규칙 검증 불가, 아트 교체 시 재작성 |

A를 고른 이유: 재미의 전제는 룰의 정확성이고, 아트 교체 때 룰을 건드리지 않아야 한다.

### 4.2 구성 요소

```
Game/Source/KnightsGame/
  KnightsRules.h/.cpp      룰 코어: 상태, 단계, 입력 검증, 정산, 승패. 엔진 헤더 금지(표준 라이브러리만).
  KnightsAi.h/.cpp         AI 판단. 공개 정보 뷰만 입력으로 받는다. 엔진 헤더 금지.
  KnightsBoardController.h/.cpp   게임 씬 스크립트(ScriptComponent): 코어를 소유, UI 생성·갱신, 입력, 연출 타이밍.
  KnightsTitleMenu.h/.cpp  타이틀 씬 스크립트: 제목, "게임 시작", "종료" 버튼.
Game/Tests/
  KnightsRulesValidation.cpp   룰 코어 + AI 단독 테스트(엔진 링크 없음).
  ValidateKnightsRules.ps1     cl로 위 파일과 코어만 빌드·실행. PlaygroundValidation 스크립트 방식을 따른다.
Game/Content/Scenes/
  KnightsTitle.json, KnightsGame.json
```

- 새 `.cpp/.h`는 `Game/Game.vcxproj`와 `.filters`에 등록한다(와일드카드 아님).
- 스크립트는 기존처럼 `RTTR_REGISTRATION`으로 등록한다(`SceneChanger` 참고).

### 4.3 룰 코어 (KnightsRules)

- 단계(phase) 열거형으로 진행: `RoundStart → FlagPlacement → FlagReveal → KnightPlacement → KnightReveal → Resolution → RoundEnd → (다음 라운드 | GameOver)`.
- 코어는 **시간 개념이 없다**. 컨트롤러가 "다음 단계로"를 호출해 진행시킨다(연출 대기는 화면 쪽 책임).
- 입력 API: 플레이어별 깃발 제출(지역 2개), 기사 배치 제출(지역별 인원). 잘못된 입력(같은 지역 2개, 깃발 없는 지역에 배치, 보유 초과, 증원 지역에 배치)은 거부하고 이유를 돌려준다.
- 정산 결과는 지역별 **이벤트 기록**(누가 몇 점, 누가 몇 명 잃음, 주사위 값, 받은 기사, 폐기 점수)으로 남겨 화면이 그대로 연출에 쓴다.
- 무작위: 코어가 시드를 받는 `std::mt19937` 하나를 소유. 테스트는 고정 시드, 실제 게임은 시간 기반 시드.
- 숨김 정보 보호: 코어는 플레이어 시점의 **공개 뷰**를 만들어 준다. 공개 전 단계에서는 다른 플레이어의 깃발·배치가 "제출함/안 함"으로만 보인다. AI는 이 뷰만 받는다.

### 4.4 AI (KnightsAi)

- AI 4명은 성향이 하나씩 다르다. `[제안]`
  - 공격형: 고득점 몬스터 선호, 기사를 많이 보냄.
  - 신중형: 전멸 위험을 크게 보고, 적게 보내 "작은 묶음 먼저" 이득을 노림.
  - 증원형: 기사가 적으면 증원 지역을 우선.
  - 균형형: 기대값 위주.
- 판단 근거: 공개된 몬스터 점수, 모든 플레이어의 보유 기사·점수, (배치 단계에서) 공개된 깃발 위치. 남이 몇 명 보낼지는 그 사람의 보유 기사·깃발 수로 추정.
- 같은 상황에서도 결과가 조금씩 달라지도록 가중 무작위 선택. 테스트에서는 시드 고정으로 재현 가능.
- 판단은 즉시(한 프레임 안에) 끝나야 한다. 생각하는 듯한 지연은 화면 쪽 연출로 준다.
- 구체 공식·가중치는 `[빌더 재량]`. 단, 반목표(치팅 금지)와 "명백히 손해인 수만 두지 않을 것"(예: 몬스터 점수보다 훨씬 적은 기사를 혼자 보내 확정 전멸)은 지킨다.

### 4.5 화면 (KnightsBoardController, 임시 2D UI)

캔버스 기준 해상도 1920×1080, `UICanvasComponent` 화면 공간. 폰트는 기본 Pretendard.

```
┌──────────────────────────────────────────────────────────────┬───────────────┐
│ 라운드 3 / 8      단계: 깃발을 2개 꽂으세요                  │ 점수판        │
├──────────────────────────────────────────────────────────────┤ ■ 나    7점 5명│
│ [고블린 둥지 1~3]  [오크 야영지 3~6]  [트롤 다리 5~9]         │ ■ AI1   4점 6명│
│   몬스터 2점         몬스터 5점         몬스터 7점             │ ■ AI2   9점 3명│
│   깃발: ■■           깃발: ■            ...                   │ ■ AI3   2점 8명│
│   기사: ■2 ■1                                                 │ ■ AI4   5점 4명│
│ [드래곤 동굴 8~12] [훈련소 +1]        [용병 시장 🎲]          │ 차례 표시     │
├──────────────────────────────────────────────────────────────┴───────────────┤
│ 행동 패널: (깃발) 지역 카드 클릭으로 선택/해제, [확정]                       │
│            (배치) 내 깃발 지역마다 [-] n [+], 남은 기사 m명, [확정]           │
│ 진행 문구: "AI 2가 깃발을 꽂았습니다" / 정산 결과 한 줄                      │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 플레이어마다 고정 색상. 깃발·기사 칩은 그 색으로 표시.
- 지역 카드: 이름, 종류, 범위, 현재 몬스터 점수(라운드 시작 즉시 표시). 공개된 깃발·기사 칩.
- 점수판: 5명 점수·보유 기사 상시 표시, 현재 차례 강조.
- 깃발 단계: 카드 클릭으로 2개 선택, 정확히 2개일 때만 [확정] 활성.
- AI 차례: 한 명당 약 0.5초 간격으로 "깃발 완료" 표시. `[제안]`
- 공개: 깃발/기사 칩이 한 번에 드러난다.
- 정산: 지역별로 약 1.2초씩 카드 강조 + 결과 문구(예: "트롤 다리 승리! 나 +2, AI3 +5", "드래곤 동굴 전멸 — AI1 기사 3명 잃음", "용병 시장 주사위 4 → 2명이 2명씩"). 화면 클릭 시 다음으로 빨리 넘김. `[제안]`
- 게임 종료: 순위표(점수·기사), 승자 강조, [다시 하기](같은 씬에서 코어 재시작), [타이틀로].
- 시간 값·색·배치 세부는 `[빌더 재량]`.

### 4.6 타이틀 씬 (KnightsTitleMenu)

- 화면 가운데 "기사단 게임" 제목, [게임 시작], [종료] 버튼.
- [게임 시작]: `SceneManager::OpenScene("KnightsGame")` 성공 시 현재 씬 `UnloadScene` (`SceneChanger`와 같은 방식).
- [타이틀로]는 반대 방향으로 같은 방식.
- [종료]: `Application::Quit()`.

### 4.7 엔진 연동 제약

- **커서**: `GameApp`은 기본으로 커서를 숨기고 가둔다. 두 스크립트는 `Start`에서 `InputManager::SetCursorRequested(true)`, `OnDestroy`에서 `false`를 호출해 클릭 가능하게 한다(`LeverConsole` 참고). Esc 동작(첫 번째 해제, 두 번째 종료)은 그대로 둔다.
  주의: 씬 언로드는 지연 처리되어, 씬 전환 때 이전 씬의 `OnDestroy`가 새 씬의 `Start`보다 늦게 불려 커서 요청을 꺼 버릴 수 있다. 두 스크립트가 `Update`에서 매 프레임 `SetCursorRequested(true)`를 다시 거는 식으로 게임 스크립트 안에서 해결한다(엔진 수정 없음). `[제안]`
- **시작 씬**: `Game/Content/Game.json`의 `startupScene`을 `KnightsTitle`로 바꾼다. 다른 샘플 씬은 `-scene` 인자로 계속 열 수 있다.
- **씬 파일**: 두 씬은 메인 카메라 1개(렌더러가 요구하는 경우 대비)와 스크립트가 붙은 GameObject 1개로 구성. UI는 코드로만 만들어지며 씬에 저장되지 않는다.
- 엔진(`Engine/`) 코드는 수정하지 않는 것을 원칙으로 한다. 꼭 필요하면 별도로 알린다.

## 5. 검증

- `ValidateKnightsRules.ps1`: 룰 코어 단독 빌드·실행. 최소 포함:
  - 3.4 표의 모든 예시, 전멸 시 기사 감소.
  - 깃발 입력 검증(0/1/중복/3개 거부), 배치 입력 검증(보유 초과, 깃발 없는 지역, 증원 지역).
  - 훈련소 +1, 용병 시장 분배(d=1·n=2 → 0, d=6·n=4 → 1씩), 증원이 다음 라운드부터 반영.
  - 공개 전 뷰에서 다른 사람의 선택이 보이지 않음.
  - 8라운드 후 종료, 동점 처리.
  - 고정 시드로 AI 5인 자동 대전 다수(예: 1000게임) 완주 — 예외·불변식 위반(음수 기사, 잘못된 입력) 없음.
- 수동 확인: Game 실행 → 타이틀 → 게임 시작 → 8라운드 끝까지 진행 → 다시 하기 / 타이틀로.
